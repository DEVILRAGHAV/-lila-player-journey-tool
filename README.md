# LILA BLACK — Player Journey Explorer

A browser-based tool for exploring player behavior on LILA BLACK's maps:
paths, kills/deaths/loot events, human-vs-bot distinction, timeline
playback, and traffic/kill/death heatmaps.

**Live URL:** https://dapper-kangaroo-bc5b59.netlify.app

See `ARCHITECTURE.md` for how it's built and why, and `INSIGHTS.md` for
data-backed findings from the dataset.

## Tech stack

- **Preprocessing:** Python 3, pandas, pyarrow
- **Frontend:** Plain HTML / CSS / vanilla JavaScript, `<canvas>` rendering — no framework, no build step
- **Hosting:** Netlify, auto-deployed from this repo's `web/` folder

## Repo structure

```
preprocess.py          # flattens all raw parquet files into web/data.json
debug_ts.py             # small diagnostic script used to inspect raw timestamp encoding
analyze_insights.py     # computes the numbers backing INSIGHTS.md
web/                     # the deployed site
  index.html
  app.js
  style.css
  data.json              # generated by preprocess.py (not hand-written)
  minimaps/               # map background images
ARCHITECTURE.md
INSIGHTS.md
```

Note: the raw `player_data/` folder (1,243 parquet files provided for the
assignment) is intentionally excluded from this repo via `.gitignore` — it's
large, and everything the site needs is already baked into `web/data.json`.

## Setup — running it yourself

No environment variables or API keys are needed anywhere in this project.

### 1. Regenerate the data (only needed if you have the original `player_data/` folder)

```
pip install pandas pyarrow
python preprocess.py --input ./player_data --output ./web/data.json
```

### 2. Run the site locally

The site is fully static — no backend, no build step. Browsers block
`fetch()` of local files opened directly (`file://`), so serve the `web`
folder with any static server:

```
cd web
python -m http.server 8000
```

Then open `http://localhost:8000`.

### 3. Deploy

Push to GitHub, then on Netlify: **Add new site → Import an existing
project → GitHub → select this repo**, with:
- Build command: *(blank)*
- Publish directory: `web`

Netlify auto-redeploys on every push to `main`.

## Known limitation

`web/data.json` is about 8.4MB (the full flattened dataset). On a slow
mobile connection, the map/date/match dropdowns may take a few extra
seconds to populate on first load while it downloads — this is a one-time
fetch, cached by the browser afterward. Minimap images are loaded lazily
per-map (only the selected map downloads), so this delay is isolated to
that single JSON fetch.
